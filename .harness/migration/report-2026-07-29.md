**Original failure:** Both matrix stages (elixir 1.14.0/otp 25 and elixir 1.19.4/otp 28) failed in the "Install_Erlang_and_Elixir" step. The command `mise use --global erlang@null` / `elixir@null` used a literal "null" instead of the actual version numbers, causing: "mise ERROR Failed to install core:erlang@null: HTTP status client error (404 Not Found) for url (https://builds.hex.pm/builds/otp/amd64/ubuntu-22.04/OTP-null.tar.gz)".

### Root cause and fixes applied

1. **Matrix variable interpolation bug (root cause of the original failure).** Harness's `matrix.include` paired-combination form does not expose named axis expressions (`<+matrix.elixirVersion>`, `<+matrix.otpVersion>`) — under the hood the pair is stored as a synthetic `include` axis containing a JSON string, so the named expressions resolved to `null`. Confirmed via the raw execution metadata (`"matrixvalues":{"include":"{\"elixirVersion\":\"1.14.0\",\"otpVersion\":\"25\"}"}`). Fixed by switching to per-axis lists (`elixirVersion: [...]`, `otpVersion: [...]`) plus a `matrix.exclude` list to remove the unwanted (non-paired) combinations, which preserves named-axis expression support while still achieving the paired 1.14.0/25 and 1.19.4/28 combinations. This is the same pattern already used successfully in the ruby-client reference pipeline (simple per-axis matrix, no `include`).

2. **`erl: not found` during Elixir install (discovered after fix #1).** Once the matrix variables resolved correctly, `mise use --global elixir@<version>` still failed with `exec: erl: not found` (exit 127) during Elixir's own postinstall verification step. Root cause: the repository ships a `.tool-versions` file at its root (`elixir 1.16.0` / `erlang 26.2.1`), and mise logs explicitly warned `erlang is defined in /harness/.tool-versions which overrides the global config` — so mise was resolving `erl`/`elixir` against versions that were never installed by the CI matrix step, regardless of `mise use --global` or PATH ordering. Fixed by removing the repo's `.tool-versions` file at the start of the Install_Erlang_and_Elixir step (`rm -f .tool-versions`) before running `mise use --global erlang@<+matrix.otpVersion>` / `elixir@<+matrix.elixirVersion>`, so the global versions set by the matrix take effect.
